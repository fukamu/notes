# Navigation continuity

Parent Issue #376 keeps browser traversal, application tabs, and the connections
camera in one runtime-scoped navigation model. The delivery integration branch is
`integration/376-navigation-continuity`, created from exact `main` commit
`7c4ca43f71d5a6880d79101d8d97a7c15fba46f2`. `main` and deployment remain outside
this integration delivery.

## Managed history entries

The browser adapter owns only the `__fukamuNotesNavigationV1` namespace in
`history.state`. Its value contains version `1`, a runtime ID generated by the
browser adapter, and a positive entry ID. Replacing an entry preserves other
record-valued namespaces; pushing an entry writes only the small navigation
metadata object.

The adapter validates every state value as `unknown`. Missing, malformed,
different-runtime, or URL-mismatched state is never trusted: the visible URL is
parsed, adopted, canonicalized, and becomes a new one-entry managed segment.
Known pop events validate both entry ID and URL. Every successful traversal gets
a new activation ID even when the URL and semantic location are unchanged.

`NotesNavigationSnapshot` is referentially stable until entry, activation,
location, cause, or pending state changes. React subscribes to that snapshot,
while `getLocation()` remains available to the application controller.

## Entry-scoped camera session

One in-memory camera session belongs to one navigator runtime. It stores one
compact snapshot per managed entry:

- current card ID
- monotonic ready-layout revision
- scale
- viewport-center world coordinate

The layout key stays in the viewport boundary and is represented by the current
monotonic revision in stored entries. A stale entry activation or stale layout
cannot write. Forward entries and their camera snapshots are discarded together
when navigation creates a new forward branch. Replacing an entry keeps its camera
only while the contextual card remains the same.

On a traversed map activation, only that entry's snapshot is eligible. On a tab
activation, the entry snapshot is tried first and the latest same-card auxiliary
snapshot second. Other causes retain the existing initial fit/current-card
behavior. Valid restoration reuses the existing center-world conversion, camera
limits, resize anchoring, free-pan behavior, and persisted zoom preference.

After Back or Forward restores a ready map, the graph viewport receives focus
once with scroll prevention only if focus was otherwise lost. A connected active
control or newer pointer, touch, or keyboard activity prevents that focus move.
Normal tab activation, reload, mobile input focus, and card focus do not trigger
the traversal focus path.

## Lifetime and non-goals

Camera snapshots exist only for the current navigator lifetime. They are not
written into browser history, IndexedDB, or cross-restart storage. This work does
not add cross-card body-scroll or history-list restoration, and camera gestures
do not call the History API.
