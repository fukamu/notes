# Local Go legal and commerce runtime

Issue #510 connects terms consent, contract checkout evidence, and ordinary
period-end cancellation only for the explicit `local-fixture` application
profile. The profile is available only in local/test environments and reuses
the prepared disposable PostgreSQL database, hash-only fixture session, exact
Billing subscription, and exact Entitlement projection from Issue #509.
Production and the default/disabled profile still supply neither
`LegalRuntime` nor `BillingCancellationRuntime`; those routes remain closed.

## Fixture boundary

`backend/internal/adapters/localcommerce` owns two immutable typed sources and
one deterministic provider adapter. The source text, 980-yen monthly offer,
effective date, and initial-release classification are test data. Their
canonical hashes are shared with the browser fixtures through
`contracts/fixtures/legal/local-commerce-runtime.json`. They are not qualified
legal review, pricing approval, publication approval, or authorization to
charge anyone.

The provider has only read ports for the seeded Billing and Entitlement rows.
Before confirming an operation it requires the exact prepared owner, exact
seeded subscription and entitlement values, canonical offer hash, and internal
evidence-to-subscription mapping. It has no HTTP client, Stripe client,
credential, webhook, or write port.

- Checkout records/replays immutable terms and contract evidence in PostgreSQL,
  then returns `kind: local-confirmed` with no URL or provider reference. It
  does not create or modify a Billing row and does not charge.
- Cancellation accepts only the ordinary `period-end` effect. It returns the
  same scheduled observation for retries and performs no provider or database
  mutation. The fixture's already-seeded paid-through maximum-safe timestamp is
  also its deterministic observation/access-end sentinel.
- Account-deletion cancellation remains the separate immediate effect and is
  not routed through this adapter.

Terms-consent IDs and checkout-evidence IDs are generated by separate UUIDv7
generator functions. The browser likewise keeps the terms submission ID and
checkout submission ID independent.

## HTTP and browser behavior

The authenticated Go routes are:

- `GET|POST /api/account/terms-consent`
- `GET|POST /api/billing/checkout`
- `POST /api/billing/cancel`

Session ownership and same-origin checks run before either JSON body is read.
Bodies remain strict and limited to 2 KiB. Account, Vault, price, provider
reference, checkout URL, and cancellation target never come from the request.
Cross-owner data, stale terms/offers, identifier conflicts, dependency errors,
or malformed provider results fail closed.

The existing `/account/terms`, `/checkout`, and `/account/billing` pages call
the Go routes first. Local browser fixtures are used only when the response is
an exact, strictly decoded `404 {"error":"not-found"}`. Authentication errors,
503 responses, malformed bodies, and 404 bodies with extra fields never select
the fallback. Checkout and cancellation success bodies are strict
discriminated unions; a local confirmation cannot carry a checkout URL.

The serial Playwright server selects this profile explicitly, creates a fresh
owner-private fixture root, and installs the matching hash-only test session
cookie. Its primary commerce flow requires HTTP 200 responses from all three
Go routes and verifies that the terms and checkout submission UUIDv7 values
are distinct. Other UI error-state tests may intercept one endpoint locally;
they do not replace that whole-process assertion.

## Verification and rollback

Focused checks are:

```bash
go -C backend test ./internal/adapters/localcommerce ./internal/legal ./internal/httpapi ./cmd/notes
vitest run tests/contracts/migration-fixtures.test.ts tests/unit/http-billing-ui.test.ts tests/unit/terms-consent-ui-client.test.ts
```

The serial PostgreSQL integration test verifies acceptance/replay/staleness,
cross-owner rejection, immutable checkout evidence, scheduled cancellation,
and mapping/dependency failures against a disposable schema. Whole-process
browser verification uses only the guarded local fixture and makes no external
request.

Rollback first disables the `local-fixture` profile or removes these two
runtime values from `ServerOptions`. Preserve terms/contract evidence rows and
the prepared Billing/Entitlement rows unless the separately guarded disposable
fixture reset is intentionally run. No Stripe object or external provider
effect exists to undo. This rollback is not permission to change production
data, credentials, resources, DNS, deployment, or `main`.
